# LLM 마크다운을 깨지지 않게 채팅 채널로

mdwire 는 **렌더러가 아니라 브리지입니다.** 에이전트가 쓴 마크다운을 받아서 채널마다 그 채널이
실제로 받는 문법으로 넘깁니다. 깨진 곳을 고치고, 이스케이프하고, 길이 제한 안에서 나눕니다. 화면에
렌더링하는 일은 여전히 채널이 맡습니다.

```
LLM 마크다운  →  정규화  →  채널별 렌더링  →  안전한 분할  →  전송
```

1. **정규화.** 에이전트 출력은 온전하지 않습니다. 짝 없는 `**`, 줄을 접어 쓴 글에서 줄을 넘는 강조,
   닫히지 않은 코드펜스가 흔합니다. 렌더링하기 전에 고칩니다.
2. **렌더링.** 채널이 받는 문법으로 출력합니다. 텔레그램 HTML 은 태그 아홉 개만 받고, 슬랙
   `markdown_text` 는 표준 마크다운을 그대로 받습니다.
3. **분할.** 채널의 길이 제한을 지키되 마크업 한가운데를 자르지 않습니다. 스트리밍할 때도 청크
   경계가 `**굵게**` 안에 걸리면 안 됩니다.

## 왜 또 만들었나

기존 도구들에는 세 가지 빈틈이 있습니다. 짐작이 아니라 측정한 결과입니다.

- **깨진 입력이 오히려 보통입니다.** 에이전트가 만든 문서 60개 중 44개에 줄을 넘는 강조가 있었습니다.
  정규식 기반 변환기는 이를 잘못 짝지어 강조 범위를 *뒤집었고*, 채널은 HTTP 200 을 돌려줘서
  아무도 알아채지 못했습니다.
- **한글 처리는 짐작에 기대고 있습니다.** 어떤 변환기는 한글 옆 강조에 U+200B 를 끼우고, 어떤 변환기는
  끼우지 않습니다. 둘 다 채널에서 확인해 보지 않았습니다. 그래서 직접 측정했습니다. 슬랙 `markdown_text` 는
  CommonMark 를 따르므로 한글 조사 옆 `_기울임_` 은 깨지고 `*기울임*` 은 제대로 나옵니다. mdwire 는
  `*` 을 쓰고 아무것도 끼우지 않습니다.
- **스트리밍을 지원하는 변환기가 없습니다.** 모두 일괄 처리입니다. 문서 전체를 파싱해 AST 를 만든 뒤
  렌더링합니다. 토큰이 조금씩 들어오면 청크 경계에서 마크업이 갈라집니다.

## 대상

텔레그램 HTML, 슬랙 `markdown_text`, GitHub 코멘트(GFM), 노션 페이지, 평문, 브라우저용 HTML 을
지원합니다. 구현은 Rust 코어, CLI, npm 패키지(WASM), Go 구현이 있고 모두 같은 테스트 케이스를 통과합니다.

## 데모

[데모](/ko/demo/)는 npm 패키지를 브라우저에서 실행합니다.

- [Telegram vs Slack](/ko/demo/channels/): 에이전트 답 하나를 텔레그램용과 슬랙용으로 나란히 변환합니다.
- [Streaming](/ko/demo/streaming/): 같은 답을 렌더러 다섯 개에 스트리밍합니다.
- [깨진 마크다운 고치기](/ko/demo/repair/): 깨진 에이전트 출력을 고치기 전과 후로 비교합니다.

## 설치

```sh
npm install @minjun0219/mdwire     # npm — 번들러, Node, Bun
cargo add mdwire-core              # Rust 라이브러리 (`use mdwire::…`)
cargo install mdwire-cli           # `mdwire` CLI
go get github.com/minjun0219/mdwire/go@latest
```

[문서](/ko/docs/)에서 네 구현이 함께 쓰는 규칙([Concepts](/ko/docs/))과 언어별 API 를 볼 수 있습니다:
[npm](/ko/docs/npm/), [Rust](/ko/docs/rust/), [Go](/ko/docs/go/), [CLI](/ko/docs/cli/).
