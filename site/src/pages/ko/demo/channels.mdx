# 텔레그램 대 슬랙

에이전트 답 하나를 두 채널로 옮긴다. 보이는 것이 채널로 나가는 글자 그대로다 — 텔레그램에
`parse_mode: "HTML"` 로 넘길 본문, 슬랙에 `markdown_text` 로 넘길 본문.

예시는 [코퍼스](https://github.com/minjun0219/mdwire/tree/main/corpus/cases)에서 가져왔다 —
전부 실제로 겪은 고장이다. 입력을 직접 고쳐 봐도 된다.

<div class="wide">
  <ChannelCompare client:only="react" lang="ko">
    <p slot="fallback">WASM 빌드를 불러오는 중…</p>
  </ChannelCompare>
</div>

텔레그램은 태그를 받는다 — HTML 모드에는 헤딩도 표도 없어서 표는 고정폭 블록으로 나간다.
슬랙 `markdown_text` 는 표준 마크다운을 읽으니 출력도 마크다운이다 — 고친 뒤의 마크다운. 두
채널 모두 닫히지 않은 강조와 코드펜스는 보내기 전에 닫고, 출력 아래의 숫자는 정규화가 고친 것과
채널에 맞춰 바꾼 것을 보여 준다.

<details class="code">
<summary>이 데모의 코드</summary>

```ts
import { renderWithReport } from "@minjun0219/mdwire";

for (const channel of ["telegram-html", "slack-markdown"]) {
  const out = renderWithReport(input, channel, { from: "markdown" }); // 슬랙 레거시면 "slack-mrkdwn"
  out.parts;   // 보낼 것 — 한도에 걸리지 않으면 문자열 하나
  out.repairs; // closedEmphasis · closedFence · … · convertedMarker — 열 가지 수
  out.free();  // 결과는 WASM 메모리에 있다. 다 쓰면 놓는다
}
```

전체 컴포넌트: [`site/src/components/ChannelCompare.tsx`](https://github.com/minjun0219/mdwire/blob/main/site/src/components/ChannelCompare.tsx).
