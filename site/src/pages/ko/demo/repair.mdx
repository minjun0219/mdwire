# 정규화 전후

에이전트는 마크다운을 반듯하게 쓰지 않습니다. 강조를 열어 둔 채 넘어가고, 코드펜스를 닫기 전에 출력이
끊기고, 짝 없는 백틱을 남깁니다. mdwire 는 채널에 맞게 렌더링하기 전에 이런 문제부터 고칩니다. 이
데모는 입력과 mdwire 가 보내는 결과를 나란히 놓고 <ins>더한</ins> 글자와 <del>뺀</del> 글자를
표시합니다. 아래의 정규화 보고는 고친 것을 종류별로 셉니다.

예시는 [코퍼스](https://github.com/minjun0219/mdwire/tree/main/corpus/cases)에서 실제로 정규화가 일어나는
케이스만 골랐습니다. 입력을 직접 망가뜨려 봐도 됩니다.

정규화 보고를 보면 모델이 자기 서식을 얼마나 자주 깨는지 알 수 있습니다. 답마다 기록해 두면 에이전트가
정규화에 얼마나 기대는지도 보입니다. CLI 의 `--batch jsonl` 은 답 수백 개를 한 번에 이렇게 집계합니다.
앞의 네 가지는 고친 것이고, 뒤의 여섯 가지는 채널 때문에 바꿔 쓴 것입니다. `table-cell-overflow`
에서는 표를 다시 쓴 횟수도 잡힙니다. 노션은 예외인데, 노션에는 표가 `<table>` 태그로 나가기
때문입니다([Concepts](/ko/docs/#정규화-보고)).

<details class="code">
<summary>이 데모의 코드</summary>

```ts
import { renderWithReport } from "@minjun0219/mdwire";

const out = renderWithReport(input, "slack-markdown");
const r = out.repairs;
out.parts.join(""); // 보낼 텍스트
r.closedEmphasis;   // 블록 끝에서 닫아 준 강조
r.closedFence;      // 문서 끝에서 닫아 준 코드펜스
r.revertedCodeSpan; // 짝이 없어 텍스트로 되돌린 백틱 런
r.droppedMarker;    // 짝이 없어 버린 **
r.rewrittenTable;   // … 그리고 채널에 맞춰 바꿔 쓴 것 여섯 가지
r.free();           // 둘 다 WASM 메모리에 있으므로 다 쓰면 해제
out.free();
```

표시는 이 페이지가 입력과 출력을 글자 단위로 비교해서 그린 것입니다. mdwire 는 바꾼 위치가 아니라
횟수만 알려 줍니다. 전체 컴포넌트:
[`site/src/components/RepairCompare.tsx`](https://github.com/minjun0219/mdwire/blob/main/site/src/components/RepairCompare.tsx).

</details>
