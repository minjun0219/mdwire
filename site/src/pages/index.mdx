# Send LLM Markdown to chat channels without it breaking

mdwire does not turn Markdown into finished output. It **tailors the Markdown an agent wrote to
each channel**: repaired, rewritten into the syntax that channel accepts, and split within its
length limit. Rendering is still the channel's job.

```
LLM markdown  →  normalize  →  render for channel  →  split safely  →  send
```

1. **Normalize.** Agent-written Markdown may not render correctly through a standard
   Markdown converter: unpaired `**`, emphasis that spans a line break in wrapped prose, unclosed
   code fences. Repair before rendering.
2. **Render.** Emit the syntax the channel accepts. Telegram HTML allows nine tags; Slack
   `markdown_text` takes standard Markdown directly.
3. **Split.** Respect the channel's limit and never cut through markup — including while
   streaming, where a chunk boundary must not land inside `**bold**`.

## Why another one

We found three gaps in existing tools: emphasis spanning lines is common, common Korean notation collides
with Markdown, and chat-channel converters ignore streaming. [Why another one](/why/) goes into each, and
[Cases](/why/cases/) shows the real failures.

## Targets

Telegram HTML, Slack `markdown_text`, GitHub comments (GFM), Notion pages, plain
text, and HTML for the browser — from a Rust core, a CLI, an npm package (WASM), and a Go implementation held to
the same test cases.

## Install

```sh
npm install @minjun0219/mdwire     # npm — bundlers, Node, Bun
cargo add mdwire-core              # Rust library (`use mdwire::…`)
cargo install mdwire-cli           # the `mdwire` CLI
go get github.com/minjun0219/mdwire/go@latest
```

The [docs](/docs/) cover the shared concepts and the API of each: [npm](/docs/npm/),
[Rust](/docs/rust/), [Go](/docs/go/) and the [CLI](/docs/cli/).
