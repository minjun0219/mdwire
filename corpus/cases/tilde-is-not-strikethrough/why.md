실제 문서 더미를 훑다 나왔다. 물결표 하나를 취소선 마커로 읽어서, **물결표가 사라지고
멀쩡한 문장이 통째로 그어졌다** — `~40km … ~22km` 의 두 물결표가 짝지어지면서 그 사이가
전부 취소선이 된다.

한국어에서 물결표는 근사값(`~40km`)과 범위(`5~6월`)에 늘 쓰인다. 취소선보다 이쪽이 훨씬
흔하다. 그리고 `~~` 로 한정해도 잃는 것이 없다 — **그게 문법이기 때문이다.** GFM 도 슬랙
`markdown_text` 도 취소선을 `~~` 로 적는다. 홀로 선 `~` 를 취소선으로 읽는 것은 레거시
`mrkdwn` 과 MarkdownV2 의 *출력* 규칙이지 입력 문법이 아니다.

취소선 자체는 드물지 않다. 그래서 같은 케이스에 `~~…~~` 도 함께 넣어, 고치면서 진짜
취소선을 잃지 않았는지 본다. 채널별 표기가 갈리는 것도 여기서 확인한다 —
`markdown_text` 는 `~~`, 텔레그램 HTML 은 `<s>`.

**GitHub 은 홑 `~` 도 취소선으로 읽는다**(실측 2026-09-30, `POST /markdown` gfm). 이 입력을
그대로 내면 `~40km … ~22km` 사이가 그어진다 — 입력에서 고친 고장이 출력 쪽에서 다시 난다.
그래서 GitHub 으로는 글자로 남은 `~` 를 `\~` 로 탈출해 낸다. `~~` 취소선은 그대로다.

**옵시디언에서도 물결이 깨진다는 제보가 왔다**(2026-10-16). GitHub 에서 잰 것과 같은 고장으로 보고
`obsidian-markdown` 도 글자 `~` 를 `\~` 로 낸다. 옵시디언의 어느 보기(읽기 · 편집)에서 긋는지, `\~` 가
두 보기에서 `~` 로 보이는지는 아직 재지 않았다.
