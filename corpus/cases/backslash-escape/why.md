실제 문서 더미를 훑다 나왔다. **역슬래시 탈출을 아예 안 읽고 있었다.**

```
입력   TEST-SELF\_VCLEFT\_FRONT
전     TEST-SELF\<i>VCLEFT\</i>FRONT     기울임이 되고 역슬래시까지 남는다
후     TEST-SELF_VCLEFT_FRONT
```

`\_` 는 밑줄 한 글자지 강조 마커가 아니다. 식별자에 밑줄이 박힌 문서(서비스 매뉴얼,
API 문서)가 통째로 이 고장에 걸린다. 탈출된 대괄호도 마찬가지였다 —
`createError\[code || name\]` 이 링크로 읽혔다.

**마크다운을 그대로 내보내는 채널에서는 탈출을 지키고 나간다.** 벗겨서 맨몸 `*` 를
내보내면 저자가 글자로 쓴 별표가 그 채널에서 강조로 읽힌다 — 벗기는 쪽이 오히려 뜻을
바꾼다. 강조 마커만 지켜서도 안 된다. `\#` 를 벗기면 제목이 되고 `\[x\](url)` 을
벗기면 링크가 된다 — **그 채널의 마크다운이 읽는 글자는 전부** 지킨다. 그래서 같은 입력이 슬랙에서는 `\*` 로, 텔레그램 HTML 과 plain 에서는 `*` 로
나간다. 채널별 기대 출력이 갈리는 지점이라 세 채널을 다 넣어 둔다.

채점 쪽도 같이 고쳤다. 참조 구현이 탈출을 모르면 코어가 제대로 내도 거짓 경보가 나고,
낱말 셈과 마커 셈도 층마다 어긋난다.
