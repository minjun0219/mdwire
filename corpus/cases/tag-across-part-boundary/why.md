실제 문서 더미를 훑다 나왔다. 링크가 달린 긴 목록이 한도를 넘겨 나뉠 때, **끊는 자리가
여는 태그 한가운데에 떨어졌다.**

```
조각 0 끝   … 주소의 뒤집힌 꼴을 돌려준다 <a
조각 1 시작 href="https://…">src</a>
```

조각 하나가 곧 메시지 하나다. 양쪽 다 깨진 HTML 이라 채널이 메시지를 **통째로 거절한다**
— 조금 깨지는 것이 아니라 아예 안 간다. 실제 문서 2289건 중 8건이 여기 걸려 있었다.

끊는 자리는 공백이 정하는데 `<a href="…">` 안에도 공백이 있다는 것이 화근이었다.

**기대 출력을 두지 않는다.** 이 케이스의 고장은 "조각이 저마다 유효한가"라서, 채널별
기대 출력 파일에 조각 구분자(NUL)를 적어 넣어야 한다 — 그러면 git 이 바이너리로 보고
diff 가 안 나와서 정본이 읽히지 않는다. 대신 불변식 채점이 이 입력을 매번 훑는다.
조각마다 태그 균형을 재는 규칙이 그 고장을 그대로 잡고, 다른 언어로 된 구현을 같은
잣대에 올릴 때도 똑같이 걸린다.
