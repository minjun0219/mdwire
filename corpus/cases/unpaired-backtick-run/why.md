실제 문서 더미를 훑다 나왔다. 짝 없는 백틱 런이 **코드 스팬을 열고 블록 끝까지
삼켰다.** 뒤에 오던 강조가 통째로 코드 안에 갇힌다.

```
입력   앞부분 ``` 뒤에 **굵게** 가 온다
출력   앞부분 <code> 뒤에 **굵게** 가 온다</code>
```

블록이 끝나도록 닫는 런이 안 왔으면 그 백틱은 코드가 아니었다는 뜻이다. CommonMark 도
짝 없는 백틱 런을 글자로 본다. 되돌리기만 하고 끝내면 안 된다 — 삼킨 내용은 코드로
읽혀서 강조가 안 걸린 상태라, **도로 꺼내 다시 읽어야** 그 안의 강조가 산다.

백틱 자체는 출력에 남는다. 저자가 쓴 그대로다 — 우리가 변환 못 한 마커가 아니라
저자가 짝 없이 쓴 글자다. 채점 쪽도 같이 고쳐서, 입력에 이미 짝 없이 서 있던 마커는
세지 않는다.

같은 케이스에 **짝이 맞는 코드 스팬**도 넣어, 고치면서 멀쩡한 쪽을 잃지 않았는지 본다.
