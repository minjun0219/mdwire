# corpus

입력 하나와 채널별 기대 출력이 한 디렉토리에 산다. 구현이 몇 개든 통과 기준은 이것이다.

```
cases/<이름>/
  input.md
  telegram-html.txt
  slack-markdown.txt
  plain.txt
```

기대 출력 파일이 없는 채널은 그 케이스에서 검사하지 않는다.

## 여기 없는 것 — 분할

`DESIGN.md` 의 두 번째 고장(마크업을 만든 뒤에 자르기)은 케이스로 없다. 텔레그램 한도가
4096자라 케이스 하나가 4KB 넘는 입력을 들고 있어야 하는데, **그 4KB 를 지어내는 순간
"실제로 겪은 고장만"이라는 규칙을 우리 손으로 깨는 것**이다. 그래서 분할은
`crates/mdwire-core/tests/render.rs` 의 테스트가 지킨다. 실제로 한도를 넘긴 문서를
만나면 그때 케이스로 들어온다.

**실제로 겪은 고장만 넣는다.** 가상의 엣지 케이스는 스펙 준수 테스트지 이 라이브러리가
풀려는 문제가 아니다. 케이스를 더할 때는 무엇이 어떻게 깨졌는지 `why.md` 에 한 줄 남긴다.
